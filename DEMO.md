## DEMO-0001 - checkpoint, migrate, resume under the sovereignty rule (wow)
- **Status:** planned
- **Preconditions:** >=2 machines acting as houses (Omen laptop, Mac mini, teammates' laptops) on the same network, each running `live_agent`; the real job (Whisper transcription or embedding batch) and its model already cached locally (no downloads on stage); jobs carry access class public / swiss-only / certified; site eligibility table in `data/assumptions.yaml` (TODO). Venue Wi-Fi fallback: phone hotspot or wired switch.
- **Steps / expected output:**
  1. Start the job on house A. Dashboard: job `running`, A's tank charging.
  2. Drop A's heat signal (dashboard control). Expected: scheduler returns `migrate`/`pause`, job writes a checkpoint, status `checkpointed`.
  3. Scheduler picks an ELIGIBLE house B. Expected: job resumes on B from the checkpoint offset (not from zero).
  4. Submit a `swiss-only` job with the only free house marked non-eligible. Expected: refused, reason shown, dashboard cost-of-rule counter rises.
  5. (Optional) transcribe our own pitch audio as the live job.
- **Known-broken edges to avoid:** none recorded yet; update after every rehearsal.
- **Reset:** kill all job processes on every node; delete checkpoints (`checkpoints/` is gitignored); restart each `live_agent`; reload dashboard; set all heat signals to their scripted start values. Target < 60 s. Deployed-demo rollback line: N/A (local only).
